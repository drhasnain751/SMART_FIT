Software Requirements Specification (SRS)

for

SmartFit

Version 2.0 (As-Built)

1. Introduction

This Software Requirements Specification (SRS) document provides a comprehensive, as-built overview of the SmartFit application. SmartFit is an intelligent, web-based fitness platform designed to provide users with personalized workout and diet plans generated by a custom-built AI Expert System. This document outlines the final functional and non-functional requirements, system architecture, and design constraints based on the completed development, serving as the definitive record of the project.

1.1 Purpose

The purpose of this SRS is to accurately document the delivered SmartFit application, ensuring a clear and unified understanding of its features, capabilities, and technical implementation. It serves as a final reference for all stakeholders, detailing the system's functionalities as they were successfully built and deployed, and provides a foundation for any future development or maintenance.

1.2 Scope

SmartFit is a responsive web application that leverages a rule-based AI engine to generate personalized fitness and nutrition plans. The system is delivered with the following core functionalities:

  • User Authentication: Secure user registration and login using JWT (JSON Web Token) based authentication.
  • AI Plan Generation: A dedicated page where authenticated users input their physical attributes, goals, and equipment to receive instantly generated, personalized workout and diet plans from the backend API.
  • Workout Plan Generation: The AI provides tailored exercise routines based on the user's fitness level (Beginner/Intermediate) and selected goal (e.g., muscle gain, fat loss).
  • Diet Plan Generation: The AI offers customized meal plans designed to meet specific caloric and macronutrient targets calculated from user data.
  • Exercise Library: A filterable, hardcoded library of exercises with relevant images and embedded video tutorials for user reference and learning.

The application is accessible via modern web browsers on desktop and mobile devices. Features not included in the final scope are live personal training, real-time progress tracking, and direct messaging with coaches.

2. Overall Description

2.1 Product Perspective

SmartFit is a new, self-contained product developed from the ground up. It leverages a modern, decoupled architecture with a React single-page application for the frontend and a FastAPI microservice for the backend. This "as-built" architecture prioritizes performance, scalability, and a clear separation of concerns, making it a robust foundation for future features.

2.2 Operating Environment

SmartFit is a web-based application designed to operate in a standard client-server environment.

2.2.1 Client-Side Environment:

  • Web Browsers: The application is fully compatible with the latest versions of Google Chrome, Mozilla Firefox, and Microsoft Edge.
  • Devices: The responsive design ensures usability across desktops, laptops, tablets, and smartphones.

2.2.2 Server-Side Environment:

  • Server OS: The backend is designed to run on a standard Linux-based server environment (e.g., via Docker).
  • Database: The application uses a file-based SQLite database for user authentication data, chosen for its simplicity, ease of deployment, and suitability for the project's scale.
  • Data Source: The AI engine's knowledge base is derived from curated CSV files containing exercise and nutritional data, which are loaded into memory using the Pandas library for high-speed processing.

2.3 Design and Implementation Constraints

The project was executed under the following technical constraints and decisions, reflecting the final implementation:

  1. Frontend Framework: React

    React was chosen for its component-based architecture, extensive ecosystem (including React Router for navigation), and its ability to create a dynamic, single-page application experience.

  2. Backend Framework: Python with FastAPI

    The initial constraint to use Django was revisited. FastAPI was selected as the superior choice due to its high performance, native asynchronous support, and excellent integration with data-centric libraries like Pydantic, making it ideal for an AI-driven API.

  3. AI Engine Implementation: Rule-Based Expert System

    The initial concept of using TensorFlow/Keras was evolved into a more practical and reliable solution. A rule-based Expert System was built using Python and Pandas. This approach guarantees that generated plans are logical, safe, and adhere to established fitness principles, avoiding the "black box" problem of some machine learning models.

  4. Database: SQLite

    The initial plan for PostgreSQL was simplified to SQLite. For the project's scope, which focuses on demonstrating the AI engine and user authentication, SQLite provides all necessary functionality without the overhead of setting up and managing a separate database server, greatly simplifying development and deployment.

  5. Authentication: JWT (JSON Web Tokens)

    A token-based authentication system using JWT was implemented. This is a modern, stateless standard for securing APIs, allowing for a clean separation between the frontend and backend.

3. Requirement Identifying Technique

Use Case Modeling was selected and used to derive the functional requirements for SmartFit. This technique was highly effective as the application is user-centric and interaction-driven. By modeling the step-by-step interactions of a user (e.g., "Register Account," "Generate Plan"), we could clearly define the necessary system functions from the user's perspective, ensuring the final product directly addresses their goals.

4. Use Cases (Key Examples)

The following use cases represent the core functionality delivered in the final application.

UC-1: Register New User
Primary ActorVisitor (Unauthenticated User)
DescriptionA new visitor provides an email and a password of at least 8 characters to create a secure account.
Normal Flow 1. Visitor navigates to the Registration page.
2. Fills in the email and password fields.
3. Clicks "Create Account".
4. System validates the input and sends it to the backend API.
5. Backend hashes the password, stores the user in the SQLite database, and returns a success message.
6. Frontend shows a success alert and navigates the user to the Login page.
ExceptionsE1: If the email is already registered, the API returns a 400 error, and the frontend displays "Email already registered".
UC-2: Login User
Primary ActorRegistered User
DescriptionA registered user provides their credentials to gain access to the application's protected features.
Normal Flow 1. User enters email and password on the Login page.
2. Clicks "Sign in".
3. System sends credentials to the backend API's token endpoint.
4. Backend verifies credentials against the database, and if correct, generates and returns a JWT access token.
5. Frontend saves the token to `localStorage` and navigates the user to the homepage.
ExceptionsE1: If credentials are incorrect, the API returns a 401 error, and the frontend displays "Incorrect email or password".
UC-3: Generate Personalized Plan
Primary ActorAuthenticated User
DescriptionAn authenticated user generates a complete workout and diet plan from the AI engine.
Normal Flow 1. User navigates to the "AI Planner" page.
2. Fills out the form with their stats (age, weight, etc.), goals, and equipment.
3. Clicks "Generate My Plan".
4. Frontend sends the form data along with the JWT token in the request header to the protected backend endpoints.
5. Backend verifies the token, then runs the workout and diet generation expert systems.
6. Backend returns a JSON object containing both the workout and diet plans.
7. Frontend receives the data and displays it in a formatted, user-friendly view.
ExceptionsE1: If the user's token is invalid or expired, the API returns a 401 error, and the frontend displays an error message.

5. Functional Requirements

The following functional requirements were implemented in the final product.

FR-1: User Registration

The system shall allow a visitor to create a new user account by providing a unique email and a password with a minimum length of 8 characters.

FR-2: User Login

The system shall authenticate a user via their email and password. Upon successful authentication, the system shall issue a JWT access token to be used for subsequent requests.

FR-3: Protected Route Access

The system shall restrict access to core application pages (e.g., AI Planner, Home) to authenticated users only. Unauthenticated users attempting to access these pages shall be redirected to the login page.

FR-4: AI Plan Generation

The system shall provide an interface for authenticated users to input their personal data and fitness goals. Upon submission, the system shall call the backend AI engine and display the generated personalized workout and diet plans.

FR-5: Exercise Library Display

The system shall display a library of exercises, filterable by muscle group, equipment, and difficulty level. Clicking a filter shall navigate the user to a page showing only the relevant exercises.

6. Non-Functional Requirements

NFR-1: Performance

The API endpoints for plan generation shall process the request and return a response within 5 seconds under normal load. Web pages should achieve a satisfactory score on standard web performance metrics.

NFR-2: Usability

The user interface shall be responsive and usable on both desktop and mobile screen sizes. Navigation shall be clear and intuitive, with interactive elements providing immediate visual feedback.

NFR-3: Security

User passwords shall be securely hashed using the Argon2 algorithm before being stored in the database. Communication between the client and server for protected endpoints shall be secured via JWT Bearer authentication.
